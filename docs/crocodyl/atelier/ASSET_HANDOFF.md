# Crocodyl 3D and cinematic asset handoff

Date: 2026-09-17. Working branch: `feat/immersive-visuals` (PR #11).

## Scope and approval status

The first pass establishes an offline equipment viewer, portable meshes, a reproducible art pipeline and image assets. It does **not** establish that the equipment is a faithful replica of a particular commercial product, that the body atlas is 3D, or that any depicted technique is correct.

Respect the newer owner direction in [`../visuals/ARROW_FIRST_ART_DIRECTION.md`](../visuals/ARROW_FIRST_ART_DIRECTION.md): **arrow first**. The existing recurve, arrow and target models are unapproved generic studies. Do not keep expanding the bow collection or promote the models as finished instructional assets. The square target-paper correction remains separate from the circular scoring geometry and is not completed by adding atmospheric imagery.

The visual separation vectors are presentation aids, not assembly or disassembly instructions. No internal mechanism is verified merely because it is modelled.

## Viewer behaviour already implemented

- Drag/keyboard orbit, pinch/wheel zoom, reset, named-part focus and separate/reassemble.
- Dark and light presentation, desktop and mobile layouts, optional turntable.
- Idle rendering stops. The host exposes pause/resume, and the viewer responds to page visibility and reduced motion.
- The native host serves an allowlisted local HTTPS origin. File/content access and outbound loads are blocked; there is no JavaScript-to-native data bridge.
- Failure text and component descriptions are available when WebGL cannot initialize. A lost graphics context currently asks the user to reopen the screen.

The minimal renderer supports this package's static GLB subset, not arbitrary animation, skins or third-party model features. The GLBs themselves are standard files and can be imported into a full renderer later. Do not introduce an external CDN to make a viewer change easier.

## Reproduction and evidence

```sh
python3 tools/atelier/build_assets.py
python3 tools/atelier/test_assets.py
# Install the authoring-only dependencies pinned in atelier-quality.yml, then:
python3 tools/atelier/render_qa.py
# Android compilation:
./gradlew :app-android:assembleDebug -PwithAndroid --no-daemon
```

Use the actual Actions result and its `browser-report.json`, not an old commit message, as the browser-verification record. Seven mesh/export checks passed locally and in CI on the initial bake. The first complete browser pass produced real model screenshots with 57 of 58 checks passing; its outstanding assertion concerned the timing of the reduced-motion change. Later revisions must be judged by their own report. These are separate from physical Android/WebView, rotation, memory, thermal, accessibility and device-lifecycle verification.

Do not describe a rendered screenshot as evidence that a model matches real equipment. The current tube primitive's cap winding also deserves an explicit regression check before treating the files as approved portable production assets; the custom two-sided renderer can conceal winding mistakes.
